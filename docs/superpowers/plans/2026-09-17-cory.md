# Cory Daily Tracker Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add persistent Cory account, character, and daily pickup/completion tracking alongside the existing tracker.

**Architecture:** Keep Cory state in the existing App localStorage state. Put game-day calculations and status transitions in `domain.js`; render the feature in focused `CoryPanel` components. The existing dashboard remains unchanged behind a top-level tab switch.

**Tech Stack:** React, Vitest, Testing Library, localStorage.

## Global Constraints

- Three editable account slots.
- Each account supports up to nine editable characters through `Dodaj postać`.
- Game day rolls over at `02:00` local time.
- `Wczoraj` and `Dzisiaj` are editable; `Jutro` is empty and read-only.
- Status progression is `puste -> odebrane -> zrobione`; `zrobione` is locked for that day.
- Empty, received, and completed statuses render white, blue, and green.

```js
export function createInitialCoryState() {
  return { accounts: [{ id: 'account-1', name: 'Konto 1', characters: [] }, { id: 'account-2', name: 'Konto 2', characters: [] }, { id: 'account-3', name: 'Konto 3', characters: [] }], statuses: {} }
}

export function getGameDateKey(value) {
  const date = new Date(value)
  if (date.getHours() < 2) date.setDate(date.getDate() - 1)
  return getLocalDateKey(date)
}

export function advanceCoryStatus(status) {
  if (status === 'received') return 'completed'
  if (status === 'completed') return 'completed'
  return 'received'
}

export function getCoryStatus(state, dateKey, accountId, characterId) {
  return state.statuses?.[dateKey]?.[accountId]?.[characterId] ?? ''
}
```
